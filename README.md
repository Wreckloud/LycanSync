# LycanSync

面向 4–8 名熟人的 Windows 游戏语音和多人屏幕共享项目。

当前为测试开发版，提供持久化群组、语音、屏幕共享、文字/图片/文件群聊，以及 Vue 界面与 Electron 桌面客户端。已接入邀请身份、桌面自动登录和全局在线/闲置/离线状态。Windows 桌面端屏幕分享已接入 Rust 原生视频与声音链路，浏览器端仍使用 Chromium；屏幕声音的真实双客户端设备验收、长时间运行和安装版设备验收尚未完成。已提供 Windows x64 安装包和 Linux 单机部署打包入口；完整的游戏与音乐活动检测、独立于屏幕共享的系统音频尚未完成。账号准入已加入管理员激活、单人邀请和成员恢复；数据库迁移、安装版唤起及端到端流程仍待验收，QQ 尚未开通。

## 打包与独立服务器测试

Windows 桌面安装包包含 media-helper、media-bridge 和 activity-helper，无需测试电脑自行安装 Rust 或 Node：

```powershell
$env:LYCANSYNC_PACKAGED_API_URL = "https://你的服务器地址"
# 可选：独立更新站点；未指定时使用上述地址的 /downloads/。
# $env:LYCANSYNC_PACKAGED_UPDATE_URL = "https://你的更新站点/downloads/"
npm --prefix apps/web run package:desktop
```

产物位于 `release/desktop/`，包括未签名 NSIS x64 安装程序、同名 `.blockmap` 和 `latest.yml`；内置微软 VC++ x64 运行库并按需安装。打包必须指定 HTTPS 服务器地址；运行库默认从 Visual Studio 2022 Build Tools 的 Redist 目录获取，其他位置用 `LYCANSYNC_VC_REDIST_PATH` 指定微软原版文件。安装完成可直接启动，在未登录页面修改服务器地址并重启；选择保存在用户目录，升级不会覆盖。安装版启动、升级、自动启动、原生媒体和卸载仍需在 Windows 10/11 验收。

每次发布先递增 `apps/web/package.json` 和 `package-lock.json` 中的应用版本，再重新打包；不得覆盖已发布的同版本安装包。发布时先上传版本化安装包和 `.blockmap`，最后更新 `latest.yml`。修改源码或提交 Git 不会更新已有安装包。

Windows 安装版每次启动只检查一次更新，不定时轮询。检查最多等待 10 秒；发现新版后在恢复登录、启动活动检测及媒体之前下载，经更新库校验后静默安装并重新打开。下载期间可选择“暂不更新”；检查、下载或校验失败会提示并继续使用旧版，不在通话中或普通退出时补装。更新源固定在安装包中，不随用户修改业务服务器改变；开发和浏览器入口不检查更新。旧版首次接入需手动安装 0.0.4 或以后版本；设置的“客户端”栏目可查看当前版本及状态，也可手动“检查更新”。手动发现新版后显示重启确认，取消不打断使用；选择“重启更新”会正常结束当前通话、共享和远控并重启，再复用启动下载、校验和安装流程，不在业务界面另建下载链路。本机 Windows 10 已验证 0.0.4 → 0.0.5 自动下载、静默升级和重新打开，账号凭据与服务器配置保留；新的手动确认重启入口及其他 Windows 环境仍需实机验收。当前未签名版本仍可能被安全软件阻止，不能保证系统级安装失败能在原进程中恢复。

Linux 部署包包含后端 JAR、Dockerfile、Compose、HTTPS 入口和部署说明：

```powershell
mvn -f services/api/pom.xml package
./deploy/package-server.ps1 -DesktopInstaller ./release/desktop/LycanSync-0.0.10-windows-x64-setup.exe
```

产物位于 `release/server/`。部署步骤见 [服务器部署说明](deploy/server/DEPLOY.md)，支持域名证书和内网 VMware 测试 CA 两种明确配置。服务器使用 `rtc-server` profile；`rtc-local` 的本机监听约束保持不变。服务器首次运行需要联网获取 Docker 镜像，并执行数据库迁移；本包不包含现有数据库、聊天文件或密钥。

## 运行环境

- 后端：JDK 17、Maven。
- 本地数据库：Docker Desktop（Windows 使用 WSL 2），包含 Docker Compose。
- 浏览器客户端：Node.js 22.12+、npm，以及支持屏幕采集的桌面 Chrome / Edge。

## 启动本地数据库

后端需要 PostgreSQL 18.6。

1. 启动 Docker Desktop。
2. 将根目录 `.env.example` 复制为 `.env`，一次性设置随机的 `POSTGRES_PASSWORD`、`LIVEKIT_API_KEY` 和至少 32 个字符的 `LIVEKIT_API_SECRET`。Compose 使用同一个文件管理全部基础服务，即使只启动数据库也会先校验这些配置。已有 `.env` 时不要覆盖。
3. 在仓库根目录执行：

```powershell
docker compose up -d --wait postgres
docker compose ps
```

默认连接地址为 `127.0.0.1:5432`，数据库名为 `lycansync`，用户名为 `postgres`，密码为 `.env` 中的 `POSTGRES_PASSWORD`。如果 Windows 保留了 5432 端口，可在 `.env` 设置 `POSTGRES_PORT=55432`，并让后端使用对应的 `DB_URL`。该管理员账号仅用于本地开发。

## 启动后端

后端从仓库根目录或 `services/api` 启动时读取根 `.env`，默认使用其中的 PostgreSQL 端口和密码；同名环境变量优先。在仓库根目录执行：

```powershell
$env:ACCOUNT_MODE = "invite"
$env:ACCOUNT_PUBLIC_URL = "https://你的服务器域名"
mvn -f services/api/pom.xml spring-boot:run
```

首次启动会自动执行数据库迁移。默认端口为 `18080`，可通过环境变量 `SERVER_PORT` 修改。普通模式没有配置 `server.address`，不能仅凭下面的 `localhost` 访问地址认定后端只监听本机；`rtc-local` 模式才明确绑定 `127.0.0.1`。所有运行环境统一使用邀请登录，不提供用户名密码注册入口。

- 初始化信息：<http://localhost:18080/api/system/initialization>，返回初始化状态和服务器 UTC 时间。
- 健康检查：<http://localhost:18080/actuator/health>
- 接口文档：<http://localhost:18080/swagger-ui.html>
- OpenAPI JSON：<http://localhost:18080/v3/api-docs>


## 账号准入与测试隔离

默认 `ACCOUNT_MODE=invite`。使用独立的新数据库和 `ACCOUNT_PUBLIC_URL=https://服务器域名`；已有测试密码账号的数据库不能直接切到正式模式。`ACCOUNT_SERVER_NAME` 为页面显示名。

1. 首次启动将一次性管理员激活链接写入 `ACCOUNT_BOOTSTRAP_FILE`（默认 `./var/bootstrap/admin-activation.txt`），不通过公开接口或日志提供。激活有效期 12 小时；未激活时重启会生成新链接，旧链接失效。部署侧读取方式见部署说明。
2. 打开链接网页后下载应用，保留此页面，安装后点击“打开应用”；服务器和链接会自动带入客户端，再由用户确认激活、加入或恢复。已安装可直接唤起，无需复制凭据。公共安装包不携带私人链接，预览和下载不创建账号、不消耗链接，也不自动替换已登录账号。确认激活或加入后可修改资料，也可跳过；默认昵称为“行者 + 编号”，头像为随包默认图片，签名为空。
3. 服主设置中的“邀请与成员”可生成“邀请新朋友”（3 天）和“恢复成员登录”（12 小时）。每条链接只供一人使用，成功后失效。恢复保留成员身份、资料和权限，并使旧会话失效；该入口不恢复服主账号。
4. 面板可查看待使用、已完成、过期、撤销及上次失败。服务器确认的失败不消耗链接；客户端未送达的请求不能记录成服务器失败。重新生成会作废旧链接；生成响应后应立即复制，服务器不保存原始链接。响应丢失时重新生成未使用链接。
5. 客户端以独立重试凭据支持兑换成功但响应丢失后的 2 分钟内重试，不新增账号或替换为另一会话；原会话已结束时拒绝重试。不要分享激活或恢复链接给其他人。
6. 桌面会话由主进程使用系统加密存储，30 天未使用后过期；一个账号只保留一个会话。本机记住服务器，换电脑请向服主要恢复链接。浏览器开发会话只保留在内存。
7. QQ 目前显示尚未开通，不提供模拟授权。待获得 QQ 应用凭据并完成固定回调部署后，再实现首次可选绑定、设置中绑定及昵称头像导入；暂不支持解除或更换绑定。

本机与虚拟机初期联调统一连接 HTTPS 邀请服务器，经过首次服主激活、邀请新朋友或恢复成员登录。用户名密码的控制器和数据准备代码只保留在 `src/test`，不进入后端部署包；`test-fixtures` profile 仅隔离自动化测试的启动激活文件，不是供客户端使用的登录模式。生产启动拒绝 `ACCOUNT_MODE=test`。

自定义头像由服务器统一为保留透明度的 256×256 PNG；随包默认头像可原样保留。昵称与签名沿用设置中的保存路径。尚无账号封禁、服主转让或服主自助恢复；部署侧需保管好会话与数据库备份。未签名安装包、正式网络与真实登录流程仍需验收。

账号设置中的资料自动保存；保存失败会恢复最近一次已确认保存的值，并显示错误，切换栏目、返回应用或退出登录可以继续。首次资料卡通过“保存并进入”提交，失败可重试，也可选择“跳过”。请求超时不代表服务端一定未写入，后续刷新以服务端资料为准。

## 群组

登录后可以创建私密群组。单击群组头像预览成员，悬停显示群名称；双击头像或点击耳机图标加入该群语音。新群只有创建者，其他账号需由群主添加，或在“创建／加入”中输入当前群组邀请码。群主可搜索和分页查看服务器已有成员、修改资料、管理成员、转让群主及解散群聊，不能邀请服务器外的人；服务器准入仍由服主控制。成员可以退出，群主须先转让或解散。群主转让后原群主变为普通成员；转让和移出成员会更换邀请码，现有成员不受影响。邀请码仅授予群成员资格，不会自动连接语音或开启麦克风。预览其他群组不会切换正在进行的语音。

成员制迁移保留账号、群资料和聊天记录，但此前测试版的全员访问不转换成成员资格：旧群仅保留群主，其他人需重新添加。聊天、图片、文件、成员状态和语音入口均限制为当前群成员。退出／移出成员只断开该成员的语音、共享和远控，其他成员不受影响；Caddy 在每次信令连接、重连和凭证验证时重新检查当前成员资格，不仅检查旧凭证的签名。客户端解散前需输入完整群聊名称并确认；解散会删除群组与聊天记录、结束语音并回收附件。

群组列表、创建和详情对应 `GET /api/groups`、`POST /api/groups`、`GET /api/groups/{groupId}`。成员列表来自当前群组成员关系；服务器账号邀请与群组成员邀请是不同入口，新账号不会自动加入已有群组。

个人及群组头像只接受 PNG/JPEG，不按原图文件大小拒绝；成功解码后才打开裁剪器，失败保留原头像。已有头像点击后可继续编辑，也可更换图片；继续编辑使用已保存的头像，不能恢复之前裁掉的原图内容。统一使用铺满图片的方形取景器，拖动定位、滚轮在 1–9 倍间缩放；旋转标尺默认居中 0°，拖动刻度或用键盘调整 −180° 至 +180°。应用中的个人圆形头像和群组圆角方形头像不变。原图只在本机预览，裁剪为 512×512 PNG 后提交；服务器将不合规图片规范为保留透明度的 256×256 PNG，已符合尺寸和格式的图片通过校验后原样保留。保留必要资源保护：本机解码后最多 4000 万像素，服务器裁剪载荷最多 1024×1024、2 MiB，桌面对应 JSON 请求最多 3 MiB；这些不限制正常原图选择，异常请求显示明确原因并保留草稿。

头像字段和数据库结构不变，旧客户端裁剪图片仍可保存。上线此链路时先更新后端、再更新客户端；旧后端的 96 KiB 校验不能接收新客户端的复杂裁剪图。历史头像不批量改写，重新保存自定义头像时才规范化。

## 群聊消息

当前支持文字、PNG/JPEG 图片和普通文件消息。一条消息可附带文字和一张图片或一个文件；加号可多选任意文件并按原始字节发送，图片作为文件卡片显示。拖入或粘贴 PNG/JPEG 会在浏览器端压缩后作为图片发送；其他格式作为普通文件原样发送。图片仍受服务端 5 MiB 文件和 829 万像素限制；普通文件默认每个不超过 100 MiB，服务器累计存储默认不超过 10 GiB。输入框使用多行编辑：Enter 发送，Shift+Enter 换行；中文输入法组合输入期间不会误发送。

群聊接口包括消息分页、`POST /api/groups/{groupId}/messages`（图片使用 `multipart/form-data`）、`POST /api/groups/{groupId}/files`（文件使用原始二进制流）、图片附件读取和 `GET /api/groups/{groupId}/files/{attachmentId}`（文件下载）。消息列表只返回附件元数据；图片按需读取并在组件销毁时释放 object URL，文件下载按流写入用户选择的位置。普通文件内容保存在后端私有目录，数据库只保存元数据；下载仍要求认证并检查群组访问权限。

文件传输配置：`CHAT_FILE_STORAGE_DIR` 指定服务器私有存储目录（默认 `./var/chat-files`），`CHAT_FILE_MAX_BYTES` 设置单文件上限（默认 `104857600`），`CHAT_FILE_STORAGE_MAX_BYTES` 设置普通文件累计容量上限（默认 `10737418240`）。目录不得映射为公开静态资源。文件传输上线前应备份 PostgreSQL 和该目录；恢复时需要使用同一时间点的数据与文件副本。

可见群组每 2 秒自动获取新消息，切换群组或窗口重新获得焦点时立即刷新，不提供手动刷新按钮。消息正文支持选择、复制，正文中的 HTTP/HTTPS 超链接可直接打开系统浏览器。

## RTC 接口与后端调试

本机与虚拟机的人工联调使用部署说明中的 HTTPS 邀请服务器，不再启动旧密码测试环境。下述 `rtc-local` 只用于后端开发与接口检查，媒体地址仅适用于本机；不要直接暴露本地 LiveKit 端口。

1. 确认根目录 `.env` 已按上文配置。API key 使用字母、数字、下划线或短横线；不要提交真实凭证。
2. 使用同一个 Compose 文件启动 PostgreSQL 和本地 LiveKit 1.13.6：

```powershell
docker compose config --quiet
docker compose up -d --wait
```

3. 填写 `.env` 中的数据库和 LiveKit 配置，再启动：

```powershell
$env:ACCOUNT_MODE = "invite"
$env:ACCOUNT_PUBLIC_URL = "https://你的测试服务器域名"
mvn -f services/api/pom.xml spring-boot:run "-Dspring-boot.run.profiles=rtc-local"
```

此开发实例也需要独立数据库和指向它的 HTTPS 入口，不能复用旧密码账号数据。仅运行单元测试不需要启动该实例。IDEA 工作目录设为仓库根目录或 `services/api`，Active profiles 设为 `rtc-local`；其他工作目录请通过 `spring.config.additional-location` 指定配置位置。

后端只监听 `127.0.0.1`；LiveKit 默认使用 `7990/TCP`（信令/API）、`7991/TCP`（媒体回退）、`7992/UDP`（媒体），并且只映射到本机。端口可在 `.env` 修改；当前不支持朋友从其他电脑接入。

可从 `http://127.0.0.1:18080/v3/api-docs` 重新导入 Apifox，然后发送：

```http
POST /api/rtc/token
Content-Type: application/json
Authorization: Bearer <当前会话>

{"groupId":"<现存群组的 UUID>"}
```

响应包含 `serverUrl`、`roomName`、`participantIdentity`、`token` 和 `expiresAt`。房间名由群组独立的语音房间键确定，身份与昵称取自已登录账号；仅当前群成员可申请凭证。同账号在另一台设备加入时，LiveKit 会断开旧连接。语音链路使用麦克风、屏幕视频、可选的原生屏幕声音、订阅、更新自己的收听状态，以及发送自定义入场音所需的房间数据流；不开放摄像头或房间管理权限。持久群聊仍只使用业务 HTTP 接口，不经过 LiveKit 数据通道。

未加入语音时可查询当前群组的安全摘要：

```http
GET /api/rtc/room-summary?groupId=<现存群组的 UUID>
Authorization: Bearer <当前会话>
```

该接口向已登录账号返回 `participantCount` 和按加入顺序排列的 `participants`（含 `participantIdentity`、`displayName`），不返回头像、麦克风、发言、收听或屏幕共享状态。

左侧群组栏使用 `GET /api/rtc/room-occupancies` 一次读取全部可访问群组的当前语音人数，只返回 `groupId` 和 `participantCount`，不重复返回成员资料。群头像右上角出现绿色扬声器徽标表示该群当前有人在语音中；人数最多随自动刷新延迟约 15 秒。

凭证用于 10 分钟内首次加入，不代表 10 分钟后强制结束通话。签发成功只证明后端生成了凭证，不保证 LiveKit 在线或媒体连接成功。未启用 `rtc-local` 或部署用的 `rtc-server` 时，已认证请求返回 404（匿名请求先返回 401），也不会出现在 OpenAPI 文档中。

私密群的部署必须使用同版本 `deploy/server/Caddyfile` 或内网版本 `Caddyfile.lan`：只开放信令连接与验证路径，内部校验 `/internal/rtc/access` 不对外开放，LiveKit HTTP 信令端口不直接映射到公网。缺少网关校验时，自建 LiveKit 会接受仍有效的旧凭证；不能单靠客户端离房或缩短有效期实现撤权。网关／数据库暂时不可用时拒绝新连接和重连，不中断其他成员已建立的媒体连接。本机直连 `rtc-local` 仅用于调试，不提供这一网关边界。

部署的 LiveKit 还将签名入房事件发送到内部 `/internal/rtc/events`，复核已通过预检但在撤权后才完成入房的连接，并只断开该成员。事件复核是异步的，不承诺这种并发窗口下零帧媒体暴露；需同时保留网关预检与签名事件复核，不能将事后踢人当成连接前的权限检查。

## 启动浏览器客户端

浏览器客户端使用 Vue 3、TypeScript 和 Vite，实时音视频使用 LiveKit JavaScript SDK。

先按部署说明准备 HTTPS 邀请服务器，再打开一个终端，在仓库根目录执行：

```powershell
cd apps/web
npm ci
npm run dev
```

访问 `http://127.0.0.1:4173` 可调试页面；完整身份和媒体联调使用桌面客户端与虚拟机安装版，通过同一邀请服务器建立身份。桌面端支持自动登录，浏览器调试会话仅保存在内存。Vite 仅监听本机，可通过 `WEB_PORT` 更换端口；浏览器 `/api` 默认代理到 `https://192.168.150.108`，可显式用 `LYCANSYNC_API_URL` 指向另一邀请服务器。测试 CA 必须受信任，不关闭证书校验。前端不需要数据库密码或 LiveKit API secret。

- 明确加入语音后默认请求麦克风；屏幕只在点击共享图标后采集。Windows 桌面使用 Rust/WASAPI 默认通讯输入设备采集并处理麦克风，浏览器继续使用 Chromium。关闭麦克风或离开房间会停止麦克风采集；停止屏幕共享不会影响麦克风。原生音频停止时会独立清理播放资源和采集会话；启动中取消也会等待迟到的启动结果并停止采集，清理失败不会跳过其余资源释放。
- 原生麦克风与屏幕声音的 Electron 缓冲最多保留 12 个 10 毫秒块；播放端积压到 4 块时延后确认，播放释放容量后继续发送，避免短时突发挤掉音频。持续过载仍丢弃最旧的等待块并计入诊断，不无限累积延迟。队列容量不等于实际端到端延迟，真实设备与网络仍需验收。
- Windows 桌面共享故障诊断保存在 `%APPDATA%\LycanSync\screen-share-error.log`：包含失败阶段、原始异常、系统／Electron 版本、GPU 状态和适配器，以及 helper 的 stderr（含原生失败阶段和 HRESULT）。文件达到约 1 MiB 时轮转，保留一份 `.previous`；不记录录音、画面、窗口标题、纹理句柄或登录凭据。使用独立用户目录时，日志随该目录保存；安装版同样可获取日志。
- 成员区域显示真实群组成员及全局在线、闲置和离线状态；状态来自独立心跳，不从是否加入语音推断。Windows 桌面端的活动 helper 目前仅识别 Steam 安装清单中的运行游戏；浏览器端不检测系统闲置或游戏，音乐活动尚未实现。文字聊天支持文本和 PNG/JPEG 图片，语音区域中的参与者来自实际 RTC 房间。
- 状态变化通过所选群组的长轮询通知客户端刷新成员快照；客户端每 20 秒发送一次心跳，只有在线状态或游戏活动变化才会通知其他客户端。桌面端继续按现有闲置规则进入“离开”。停止心跳 65 秒后，服务端每 3 秒检查一次并清除活动、判为离线；正常关窗和退出登录会先尽力上报离线。同步暂时中断时界面保留最近状态并提示该状态可能过期。
- 每个持久化群组使用独立的语音房间，预览其他群组不会自动切换通话。
- 舞台最多四路，默认按本机观察到的共享开始顺序填充；刚入房时已有共享按当前成员列表顺序进入。停止共享或主动移出会自动补位，手动移出或被替换者本次不自动返回，停止后重新共享恢复资格。“设置 → 客户端 → 自动填充舞台”按账号保存在本机，关闭后保留布局、停止自动补位，重新开启只填空位。
- 展开舞台下方的成员条后可手工放入共享；满员时替换最早进入舞台的一路。拖动画面底部的排列按钮交换或移入空位，也可聚焦该按钮使用 Alt + 方向键；移动不改变进入顺序。双击画面或点击单路观看按钮暂时只显示一路，返回恢复原布局。系统全屏和窗口内全屏也进入单路观看，不显示播放器进度条或暂停控件；退出窗口全屏后仍可用返回按钮恢复多人舞台。预览其他群不丢失当前通话的安排，离房或切换实际通话房间则清理舞台。独立观看窗口尚未实现。
- 本地原型不设置语音成员数上限；同一群组界面最多允许 8 路共享，目前为实验性客户端软限制，尚无服务端并发名额控制。四路舞台也是当前测试布局限制，不代表系统已验收的容量。
- 底栏的麦克风、耳机和共享使用分体按钮，主图标保留开关操作，右侧箭头点击展开菜单；麦克风菜单提供输入音量和输入等级，耳机菜单提供总输出音量，共享菜单提供开始／停止、更改来源、四档画质及共享中音频开关，各菜单末项进入语音设置。不新增设备选择，仍使用当前默认设备。齿轮打开整页“语音与音频”设置，包含输入等级、音量、处理选项、共享声音播放音量和麦克风试听。Windows 桌面原生麦克风使用 Sonora 的环境降噪、自动增益和高通滤波以减少低频杂音；处理开关在每个 10 毫秒音频块边界更新，输入音量在处理后应用，超过满幅会截幅并可能失真。浏览器保留 Chromium 的回声消除、降噪和自动增益；浏览器“人声增强”还包含轻量压缩，输入音量位于该压缩之前；Windows 桌面“低频过滤”仅使用高通滤波。两端处理方式不同，偏好存储字段保持兼容。桌面原生链路不提供软件回声消除，界面会将此设置标为不可用并建议使用耳机。
- 远端成员卡片的麦克风图标可单独静音，悬浮显示当前接收音量，滚轮或按住上下拖动可在本机调整到 0%–200%，默认 100%；0% 会取消该成员麦克风轨道的网络订阅，设置按本机账号保存。若浏览器阻止自动播放，可通过自己的成员卡片恢复收听并允许播放。
- 加入、离开语音以及开始或结束屏幕共享都会播放轻量提示音；其他成员加入、离开或改变共享状态时也会提示。“音效”设置可选择本机入场音效，支持 MP3、OGG、WAV、WebM，最长 5 秒且不超过 512 KiB；音效只保存在当前设备，加入语音时通过 LiveKit 发送给当时已在房间中的成员，自定义音发送或解码失败时回退到默认入场提示。
- 标准预设主层目标为 1920×1080、60 FPS，编码上限约 12 Mbps；桌面其他预设见下文。屏幕使用 H.264 双层：成员小窗请求低层，目标短边约 360 像素、最高 30 FPS、约 1 Mbps 上限；舞台和单路放大请求主层，三路或四路不会主动降到 30 FPS。同一路的多个可见位置合并为最高观看需求，不重复订阅。来源不放大，极小来源或 SDK 平台限制可能只发布一层；低层尺寸会受来源比例、窗口尺寸变化及编码器调整影响。实际画质、帧率、多路负载仍需真实设备验收。
- 共享发布与运行中切换使用同一预设的主层码率、帧率上限和网络降级偏好，并同步更新低层上限与缩放；失败回滚两层配置且保留 SDK 当前的层暂停状态，重发布沿用最新成功配置。标准与高帧率预设优先保持帧率、允许降低分辨率；文字清晰优先保持分辨率；节省流量使用平衡策略。这些是编码器偏好，不保证网络或设备不足时仍达到目标帧率。
- 打开整页设置、浏览其他群或最小化时，应用按元素与页面可见性合并观看需求，由 LiveKit 暂停不可见画面的视频传输，房间和订阅保留；返回后恢复原观看质量，语音、共享声音及自己的对外共享继续。全房间无人观看时由 SDK 的 dynacast 暂停对应发送层；观看主层时服务器可能保留低层用于网络降级。仅失去焦点不暂停。不可见的本地预览暂停播放，恢复时复用原采集流；不重新启动设备。实际恢复延迟仍需网络与设备验收，其他窗口完全遮挡应用的识别尚未保证。
- Windows 桌面共享声音复用原生 helper、命名管道和 LiveKit 独立 ScreenShareAudio 轨道。Windows 10 build 19041 及以上（含本机 build 19045）尝试进程级采集：窗口包含所选应用及其子进程，整屏采集系统声音并排除 LycanSync；窗口模式默认勾选“同时共享此应用的声音”，也可主动关闭声音。此版本范围参考 OBS 对 Windows 10 2004 及以上的支持，但不是微软对该 API 的官方保证，实际能力以启动和收音结果为准。采集失败或中断时画面和麦克风继续，且不会改用系统混音。Windows 10 build 15063–19040 使用默认 eRender 播放设备的 WASAPI 系统混音，窗口和整屏共享范围相同；此模式默认关闭，用户勾选“共享电脑播放的全部声音”后才启动，并提示它会采集其他程序和 LycanSync 播放的声音，可能产生回声。更旧系统不提供此声音采集。切换默认播放设备会停止系统混音声音，画面和麦克风继续工作。浏览器共享仍只传画面，麦克风仍由 Chromium 采集。进程级采集在 Windows 10 build 19045 上以及系统混音的真实设备收音、回声、静音段和长时间同步尚未验收。

多用户手工测试需要创建不同账号；同账号同时入房会替换旧连接。建议戴耳机，并先只在一个页面开麦，避免同一物理麦克风被多路采集造成重复声音。共享时选择普通应用窗口，避免共享当前页面产生递归镜像。

无需加入语音，也可在“语音与音频”设置中测试麦克风。已开麦时复用当前处理后的发送音轨；未入房或已关麦时只启动本机临时采集，不发布、不改变通话开麦状态。试听通过本机 Opus 编解码播放，输入等级读取测试音轨，音量和声音处理与通话共用本机偏好；不连接额外房间或服务器，也不模拟网络丢包、对方设备或对方音量。离开栏目、关闭设置或退出应用会停止测试；入房或开麦前等待测试清理，停止试听不关闭原有通话麦克风。借用的通话音轨在关麦、离房或重连后不再可用时，试听也会停止。建议戴耳机，试听时可切换环境降噪等选项比较效果；实际设备效果仍需验收。

## Windows 桌面客户端（开发版）

开发构建需要 Windows x64、Node.js 22.12+、npm、稳定版 Rust 工具链（含 `x86_64-pc-windows-msvc` target），以及带 MSVC C++ 工具和 Windows SDK 的 Visual Studio Build Tools。构建本身不需要启动后端、数据库、LiveKit 或 Vite。

在 `apps/web` 安装依赖后，可先单独执行统一构建：

```powershell
cd apps/web
npm ci
npm run build:desktop
```

它依次构建带 `shared-texture-output` 的 media-helper、Windows MSVC release media-bridge、activity-helper，再执行前端 TypeScript 检查和 Vite 构建。输出位置与 Electron 开发模式读取路径一致：

- `native/media-helper/target/release/lycansync-media.exe`
- `native/media-bridge/target/x86_64-pc-windows-msvc/release/lycansync_shared_texture_bridge.dll`
- `native/activity-helper/target/release/lycansync-activity.exe`
- 前端静态文件：`apps/web/dist/`，Worklet 脚本由 Vite 输出到 `dist/assets/`

默认桌面启动会先重新执行统一构建，只有全部成功后才启动 Electron：

```powershell
npm run desktop
```

`npm run build:media`、`npm run build:media-bridge` 和 `npm run build:activity` 可单独用于调试。所有 Cargo 构建使用增量产物，不需要或不应先运行 `cargo clean`。统一构建成功只表示源码和目标文件已编译，不代表真实设备上的屏幕、声音或麦克风行为已经验收。首次运行会下载 Electron；下载需要可访问其官方发行资源的网络。

界面开发先完成一次 `npm run build:desktop`，关闭已有客户端，再在 `apps/web` 执行 `npm run desktop:dev`。此入口启动本机 Vite 和 Electron，保存 Vue/CSS 后自动更新，不重编 Rust；关闭客户端会停止本次 Vite。修改 Electron main/preload 后需退出并重新运行此命令，修改 Rust 后需单独构建对应 helper/bridge 并重启客户端。页面仍使用 `lycan://app`，业务 API 继续由主进程代理；安装版忽略开发前端配置。热更新不代替 TypeScript 检查和正式构建，调整 RTC 等资源生命周期代码时应重新启动客户端，避免旧会话影响测试。

桌面原生共享选择器先显示来源名称，静态缩略图随后补齐；点击卡片选中后，点击“开始共享”确认。请求完成后才继续调度，不积压截图，关闭或页面隐藏时停止刷新。已有来源保持排序，名称位于统一比例的预览下方；来源分类保存在本机，上次确认的来源只在同一 helper 生命周期中仍有效时恢复选中，不自动开始共享。窗口关闭或 helper 重启时要求重新选择。底层截图仍按来源类别枚举，尚未实现单窗口定向截图；实际打开与首张预览耗时需实机验收，诊断日志中的 `enumerateSources` 和 `sourceThumbnails` 分别记录耗时，每类最多约 30 秒一次。

共享窗口最小化时改为发送提示画面，恢复后继续发送窗口画面；双客户端现场行为仍待验收。

共享选择器的来源名称先出现，缩略图随后补齐；窗口预览按原生窗口句柄匹配，不按标题猜测画面，缺失或歧义匹配时保留占位图；新窗口插入前部，已有窗口保持相对顺序。整屏来源显示“屏幕 1、屏幕 2”等名称，通过原生显示器物理位置转换后匹配 Electron 屏幕 ID 获取预览，不按标题或顺序猜测。静态预览目标为 320×180、JPEG 80，来源枚举完成后约 750 毫秒再刷新，可见预览约 1500 毫秒、选中预览约 750 毫秒尝试更新；这些是请求间隔，不保证实际更新延迟或性能提升。Electron 仍截取对应类别的全部缩略图。关闭后停止刷新并丢弃迟到结果，来源刷新失败保留旧画面但禁止确认，成功后恢复。

选择器底部使用四档画质切换与用途说明，左下“取消”或 Esc 关闭，右侧保留“共享音频”与“开始共享”；主共享按钮在共享中再次点击停止，使用显示器内 X 图标。底栏收听按钮统一使用耳机／禁用耳机，不表示系统设备类型；系统耳机类型自动识别尚未实现。

桌面选择器提供节省流量（720p/30）、标准（1080p/60）、高帧率（1080p/120）和文字清晰（1080p/30），确认开始后记住画质。分辨率保持来源比例且不放大小画面；对应编码码率上限暂为 3、12、20、8 Mbps，并非恒定流量或画质保证。共享中通过共享菜单的画质选项切换，不重启采集、不重发布轨道，也不改变共享声音或远控授权。切换失败会尝试恢复原配置；恢复失败则报告错误并停止该共享，原生停止未确认时仍禁止新采集。

共享中的音频开关只启动／停止原生声音采集及对应发布轨道，保留画面、麦克风和远控授权；成功后按进程声音／系统混音分别记忆开关，不扩大声音范围。开启失败保持未勾选并报告错误，画面继续。更改共享先重新选择来源，取消保留原共享；确认后停止原共享、撤销原远控授权，再以新来源和所选配置启动共享，不退出语音房间。新来源启动失败会明确报告，不恢复已经撤销的远控授权；音频开关及来源切换仍需双客户端真实设备验收。

原生输出允许最高 120 FPS，页面只按写入背压丢帧，不再重复按时间限帧。画质分辨率作用于送往编码器的帧，原生纹理仍使用来源尺寸；降低画质不代表原生采集和纹理开销同比下降。实际帧率受采集源、GPU、编码及网络影响，尚未实机验收。诊断页分别显示原生采集、纹理输出、编码前输入、编码、解码及播放帧率，预设值不能当作实际帧率。更新后须一起构建 helper、Electron 和前端，并重启客户端。

“设置 → 客户端 → 屏幕共享”提供隐藏共享光标与黄色边框的设备偏好，默认均关闭，下一次共享生效。光标选项仅改变发送画面，不影响本机鼠标，需要 Windows build 19041 或以上。隐藏黄色边框使用 Windows 官方授权接口，需要 build 20348 或以上、`graphicsCaptureWithoutBorder` 安装包能力及用户授权；当前开发版未配置该安装包能力，不能保证获准。授权拒绝、失败或等待超时会明确阻止本次共享，可关闭边框选项后重试；其他应用要求边框时系统仍可能显示边框。浏览器版由浏览器管理这两项行为。真实画面及授权流程仍待设备验收。

需要在一台电脑模拟多人时，先运行一次 `npm run build:desktop`，再给每个测试实例指定不同的 Chromium 用户目录：

```powershell
npx electron electron/main.cjs --user-data-dir="$env:LOCALAPPDATA\LycanSync-Test-2"
npx electron electron/main.cjs --user-data-dir="$env:LOCALAPPDATA\LycanSync-Test-3"
```

不同目录拥有独立的加密登录会话和单实例锁；每个窗口通过单独邀请加入不同账号。同一账号同时加入同一语音房间时，LiveKit 会保留新连接并断开旧连接。正常启动仍只允许一个主实例。

- 支持拖动标题栏、最小化、最大化／还原和关闭；再次启动会唤起已有窗口。
- 默认窗口为 1280×820 逻辑像素，在当前屏幕工作区居中，小屏自动缩小。内容区独立滚动，不显示默认滚动条；支持滚轮和触控板。
- 关闭最后的应用窗口即退出，不驻留托盘；退出时停止麦克风和屏幕采集。后端与 Docker 容器需要独立停止。
- 右侧成员列表底部常驻个人卡片，头像和昵称仅展示；从卡片齿轮打开整页设置，再选择账号设置、语音与音频、音效、客户端、关于与诊断。通话时主内容区底部滑出原有语音操作栏，退出后收起。齿轮和底栏各快捷菜单末项进入“语音与音频”。开机自启只在 Windows 桌面“客户端”栏目显示，安装版使用系统登录项直接启动主程序，不安装额外服务或常驻辅助进程；源码开发模式不会写入系统启动项。打开设置只切换可见界面，不离开房间或停止正常媒体。
- 共享前在窗口／屏幕列表中选择目标，可取消。Windows 桌面可按系统能力选择进程声音，或明确勾选默认播放设备系统混音；后者包含 LycanSync 的播放语音，可能产生回传。浏览器端仍只采集共享视频；不采集摄像头。
- 桌面业务请求由主进程转发到 `electron/server-config.json` 指定的服务，不依赖 Vite 代理。本机默认连接 `https://192.168.150.108`，开发模式可用 `LYCANSYNC_API_URL` 显式指定另一邀请服务器；安装版初始使用打包时的配置，可在未登录页面切换服务器；用户目录的选择优先于安装包默认值。地址不能包含路径，非本机地址必须使用 HTTPS。
- 此变量只指定业务后端；音视频服务地址仍来自后端签发的凭证。`rtc-local` 限本机，虚拟机与正式部署使用 `rtc-server` 的媒体地址和端口；修改客户端变量不会自动获得公网部署能力。

目前提供源码开发运行、Windows 安装程序与启动更新链路，尚不包含托盘或游戏内悬浮层。Windows 桌面麦克风已接入默认通讯输入端点的 Rust/WASAPI 共享模式采集，通过有界命名管道 PCM 进入当前 LiveKit 麦克风轨道；默认设备拔出、切换或采集失败时会停止麦克风并提示，不静默切回 Chromium。浏览器麦克风仍由 Chromium 采集。原生麦克风的真实设备音质、设备拔插与长时间运行尚未验收；软件回声消除不在支持范围内。屏幕声音的两种 Windows 采集模式也尚未完成真实设备运行时验收。

## 房间内远控（开发中）

当前远控输入链路依赖被控者已经开启的 Windows 原生整屏共享；同房间成员可申请控制，被控者明确允许后才接收鼠标移动、左右键、滚轮及常用键盘按键。控制者可取消申请或按 Esc 退出，被控者可随时撤销。退出控制保留当前普通共享；停止共享、离房或进入重连会撤销控制，不自动恢复授权。浏览器窗口共享和原生窗口共享不提供被控入口。

普通共享持有采集和发布资源，远控模块管理申请、授权与输入。普通麦克风、共享视频和共享声音通过明确登记的轨道白名单授予当前房间成员订阅权限；SDK 临时重发布保留轨道资格并替换 SID，主动停止或失败清理先撤销资格。原生视频帧按采集会话校验；停止视频和声音分别尝试清理，视频停止未确认时禁止再次启动原生视频采集，并提示重启客户端。

目前仍只有一路原生视频采集，尚未实现未共享时申请控制、自动切换整屏、结束后恢复原窗口、公开／私密切换及旁观者远控提示画面。当前整屏仍属于普通房间共享，不能作为私密远控使用。权限、会话隔离和清理已覆盖受控单元测试，真实 LiveKit 订阅权限、多客户端远控、系统输入释放及异常停止仍待设备验收。

需要选择屏幕编码层数时，可在 `apps/web` 运行定向合成成本测量。它默认跳过，明确启用后才启动隐藏、独立用户目录的 Electron；保留硬件加速，通过独立 LiveKit 测试房间比较 1080p/120 FPS 目标下的单层、两层和三层 H.264。测试会占用 CPU/GPU 和测试服务器资源，不宜在游戏或通话期间运行；不加载生产客户端，不采集屏幕或麦克风，也不连接业务房间。结束后关闭测试客户端并删除本次随机房间。

当前入口使用 Ubuntu 测试机 `192.168.150.108` 的 LiveKit（`wss://192.168.150.108:8443`），通过已配置的 root SSH 密钥读取 `/opt/lycansync-invite/.env`，仅在内存中签发短时测试令牌。运行前需信任测试 CA，Node 使用 `release/server/lycansync-current-local-ca.crt`；其他测试机可通过 `LYCANSYNC_BENCHMARK_SSH_HOST`、`LYCANSYNC_BENCHMARK_LIVEKIT_URL`、`LYCANSYNC_BENCHMARK_CA_FILE` 指定连接目标与 CA 路径，不跳过证书校验。

```powershell
  node node_modules/@playwright/test/cli.js test screenShareEncoding.spec.ts --config=playwright.desktop.config.ts --workers=1

  Remove-Item Env:LYCANSYNC_RUN_ENCODING_BENCHMARK

```

每项测试独立保存并附加 `encoding-cost.json`，记录环境、实际源帧率、各层分辨率、码率、帧率、编码耗时与测试进程资源采样。等待带宽估计稳定并确认全部目标分辨率后再采样；`statisticsValid: false` 表示缺层、分辨率不符、统计缺失或错误。统计有效不代表达到了 120 FPS，也不代表不同运行结果可以直接比较；比较层数前需核对实际源帧率、主层及低层输出，不能将较低帧率的低占用视为性能收益。进程 CPU 采样包含合成绘制、发送和接收开销，GPU 进程的 CPU 数值也不代表 GPU 利用率；硬件加速状态不能证明实际编码器类型。合成测试不能代替真实游戏、采集链路、异地网络或长期性能验收。

## 停止运行

先离开浏览器房间，在前端、后端终端分别按 `Ctrl+C`，然后在仓库根目录执行：

```powershell
docker compose down
```

PostgreSQL 和 LiveKit 已放在同一个 Compose 文件中。只停止 LiveKit、不影响数据库时使用 `docker compose stop livekit`。

不再使用 Docker 时，从系统托盘退出 Docker Desktop。必要时执行 `wsl --shutdown`；此命令会停止所有 WSL 发行版，请先保存其中的工作。

## 数据与密码

- 数据保存在命名卷 `lycan-sync_postgres-data` 中，`docker compose down` 会保留数据；添加 `-v` 会删除数据卷，请勿用于日常停止。
- `.env` 中的密码仅在数据库首次初始化时生效，已有数据库需通过 SQL 修改密码。
- 请勿公开 `.env` 中的真实密码；升级数据库前请另行备份，数据卷不能替代备份。
